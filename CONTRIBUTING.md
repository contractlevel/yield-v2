## Contributor License Agreement

Before any contribution can be accepted, you must sign the
[Contributor License Agreement](./CLA.md) ("CLA").

This is a legal requirement. Pull requests from contributors who have
not signed the CLA will not be considered.

**To sign the CLA:**

1. Read the full [CLA](./CLA.md).
2. Send a signed copy to `contractlevel@proton.me`, or sign via
   [CLA Assistant](https://cla-assistant.io/) when prompted on your
   pull request.

If you are contributing on behalf of your employer, your organisation
must have authorised the contribution. See Section 5(c) of the CLA
for details.

## How to Contribute

### Reporting Issues

Open an issue via the issue tracker. Include a clear description of the
problem, steps to reproduce it, and relevant environment details.

### Submitting Changes

1. Fork the repository.
2. Create a feature branch from `main`: `git checkout -b your-feature-name`
3. Make your changes. Keep commits focused and atomic.
4. Ensure your code passes all existing tests and, where appropriate,
   includes new tests covering your changes.
5. Open a pull request against `main` with a clear description of what
   the change does and why.

### Code Style

Follow the conventions already present in the codebase. Consistency is
preferred over personal style.

### Commit Messages

Use clear, imperative commit messages: `Fix null pointer in auth handler`,
not `fixed stuff`.
